ПЛАН ДЕМОНСТРАЦИИ ПРОГРАММНОГО ПРОДУКТА
========================================

Наименование продукта: HelperBot — Telegram-бот технической поддержки


1. ЦЕЛЬ ДЕМОНСТРАЦИИ
--------------------
Показать работоспособность разработанного программного продукта
HelperBot:
  - регистрация и авторизация пользователей разных ролей
    (пользователь, библиотекарь, инженер, администратор);
  - создание обращений в техническую поддержку через Telegram;
  - распределение и обработка заявок инженерами и администраторами;
  - чат с локальной языковой моделью (Qwen 2.5, через Ollama)
    для автоматических ответов на типовые вопросы;
  - микросервисная архитектура и взаимодействие сервисов по gRPC.


2. ЦЕЛЕВАЯ АУДИТОРИЯ
--------------------
  - Государственная экзаменационная комиссия;
  - научный руководитель и рецензент;
  - студенты и преподаватели кафедры.


3. ОБОРУДОВАНИЕ И ПРОГРАММНАЯ СРЕДА
-----------------------------------
Аппаратные требования:
  - ноутбук с процессором не ниже Intel Core i5 / Apple M1;
  - ОЗУ не менее 8 ГБ (рекомендуется 16 ГБ для работы Ollama);
  - подключение к сети Интернет (для работы Telegram API);
  - смартфон с установленным Telegram (для живой демонстрации).

Программное обеспечение:
  - ОС macOS 14+ / Linux Ubuntu 22.04+;
  - Docker 24+ и Docker Compose;
  - Go 1.22+ (для сборки из исходного кода, опционально);
  - современный браузер для просмотра логов и БД;
  - проектор / внешний экран для трансляции.

Состав продукта (микросервисы):
  - helperbot-tg     — Telegram-интерфейс, обработка команд и меню;
  - helperbot-core   — основная бизнес-логика, заявки, пользователи;
  - helperbot-ai     — сервис AI-чата с локальной моделью;
  - ollama           — среда исполнения языковой модели Qwen 2.5;
  - PostgreSQL       — две реплицируемые пары (master/slave) БД.


4. ПОДГОТОВИТЕЛЬНЫЕ ДЕЙСТВИЯ (за 30 минут до демонстрации)
---------------------------------------------------------
  1. Перейти в каталог инфраструктуры:
        cd helperbot-infrastructure
  2. Проверить наличие env-файлов:
        .env.helperbot-core
        .env.helperbot-tg
        .env.helperbot-ai
  3. Запустить все сервисы:
        make compose-up
  4. Проверить, что контейнеры в состоянии healthy:
        docker ps
  5. Накатить миграции БД:
        make migrate-up
  6. Загрузить модель в Ollama (если ещё не загружена):
        docker exec -it ollama ollama pull qwen2.5:1.5b
        docker exec -it ollama ollama create support -f Support.Modelfile
  7. Открыть Telegram, найти бота по имени.
  8. Подготовить три тестовых аккаунта (пользователь, инженер,
     администратор) с известными e-mail/паролями.
  9. Подключить ноутбук к проектору, проверить разрешение экрана.
 10. Закрыть лишние приложения и уведомления.


5. СЦЕНАРИЙ ДЕМОНСТРАЦИИ
------------------------

  Этап 1. Вступление (1–2 минуты)
    - Кратко представить продукт и решаемую им задачу:
      автоматизация технической поддержки в библиотеке (или ином
      учреждении) с возможностью эскалации заявок инженерам.
    - Назвать ключевые особенности: микросервисная архитектура,
      gRPC-взаимодействие, локальная LLM, репликация PostgreSQL.

  Этап 2. Архитектура (2–3 минуты)
    - Показать схему: Telegram → helperbot-tg → helperbot-core
                              ↘ helperbot-ai → Ollama (Qwen 2.5)
                                  ↓                  ↓
                          PostgreSQL (core)   PostgreSQL (ai)
                          master + slave      master + slave
    - Показать запущенные контейнеры (docker ps) и пояснить роль
      каждого сервиса.

  Этап 3. Регистрация и роли пользователей (3–4 минуты)
    - Открыть бот в Telegram, выполнить команду /start.
    - Зарегистрировать нового пользователя: ввести e-mail, пароль,
      выбрать подразделение и роль «пользователь».
    - Показать главное меню роли пользователя.
    - Параллельно показать в БД (через psql или DBeaver),
      что запись добавилась в таблицу users.

  Этап 4. Создание заявки в поддержку (3–4 минуты)
    - От лица пользователя создать обращение:
        выбрать категорию → описать проблему → выбрать приоритет.
    - Показать, что заявка сохранилась в БД (таблица requests).
    - Переключиться на аккаунт инженера / администратора,
      продемонстрировать список новых заявок, назначение заявки
      на себя, перевод в статус «закрыта».

  Этап 5. AI-чат с локальной моделью (3–4 минуты)
    - Из меню пользователя выбрать «Чат с поддержкой».
    - Задать вопрос на русском языке (например, «Как сбросить
      пароль?»).
    - Показать, что запрос уходит в helperbot-ai → Ollama,
      и пользователь получает ответ от модели Qwen 2.5
      с системным промптом службы поддержки.
    - Показать логи контейнера helperbot-ai в реальном времени:
        docker logs -f helperbot-ai

  Этап 6. Отказоустойчивость и репликация (1–2 минуты)
    - Показать, что данные реплицируются с master на slave
      (выполнить SELECT на slave-БД).
    - Кратко пояснить, как при сбое master реплика обеспечивает
      доступ к данным на чтение.

  Этап 7. Заключение (1–2 минуты)
    - Кратко перечислить продемонстрированные возможности.
    - Указать ссылки на репозитории сервисов и инфраструктуры.
    - Ответить на вопросы комиссии.


6. КЛЮЧЕВЫЕ ТЕЗИСЫ ВЫСТУПЛЕНИЯ
------------------------------
  - HelperBot построен по микросервисной архитектуре: три Go-сервиса
    (helperbot-tg, helperbot-core, helperbot-ai), общающихся по gRPC.
  - Используется локальная языковая модель (Qwen 2.5 через Ollama),
    что исключает передачу данных пользователей сторонним сервисам.
  - Реализована ролевая модель: пользователь, библиотекарь, инженер,
    администратор — с раздельными интерфейсами в Telegram.
  - PostgreSQL развёрнута с потоковой репликацией master/slave для
    каждого сервиса, что обеспечивает отказоустойчивость.
  - Вся инфраструктура запускается одной командой через
    Docker Compose, миграции применяются через goose.
